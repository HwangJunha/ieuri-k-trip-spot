# 시군구 경계 (SPEC-0030)

`district-boundaries.geojson` — 252개 시군구 원본 경계. **이 하나가 도형의 유일한
출처다.** 좌표 판정과 지도 렌더링이 둘 다 이걸 쓴다.

서버가 전달한 파일이다(클라이언트 지시 §0). `resolveDistricts` API가 삭제되면서
좌표 판정이 클라이언트로 왔고, **좌표는 이제 서버 경계를 넘지 않는다** — POL-045를
약속이 아니라 구조로 보장한다.

## 형식

- GeoJSON FeatureCollection, 252 feature, 전부 `MultiPolygon`
- 좌표는 **`[경도, 위도]`** (GeoJSON 표준). 뒤집으면 전 국토가 엉뚱한 곳으로 간다
- **구멍(hole)이 있다** — `polygon[0]`이 외곽 링, `polygon[1:]`이 구멍이다.
  전국에 몇 개뿐이지만 외곽 안이어도 구멍 안이면 **미포함**으로 처리해야 한다
- `properties`: `code`(시군구 5자리) · `areaCd`(시도 2자리) ·
  `nameKo` · `nameEn` · `nameJa` · `nameZh`

## 쓰임이 둘이고, 정밀도가 다르다

| | 무엇으로 | 왜 |
|---|---|---|
| **좌표 판정** | 원본 그대로 | 서버 PostGIS와 결과가 같아야 한다. 단순화하면 경계에서 어긋난다 |
| **지도 렌더링** | 런타임에 합치고 단순화 | 13만 점을 매 프레임 그릴 이유가 없고, 칸 안의 시군구 경계가 보이면 안 된다 |

판정은 `DistrictResolver`가, 렌더링용 조립은 `CellShapeBuilder`가 한다.

## 칸 도형은 미리 만들어 두지 않는다

**무엇을 한 칸으로 묶을지는 서버가 정한다.** `mapCells`가 칸마다
`districtCodes`를 주고, 클라이언트는 그걸로 원본을 합쳐 런타임에 도형을 만든다.

한때 이 폴더에 `korea_cells.json`이라는 161칸 도형 자산을 두었는데 **버렸다.**
그 파일은 클라이언트가 묶음 규칙을 스스로 추측해(광역시 통째, `"수원시 장안구"`
이름 정규식으로 시 단위 묶기) 만든 것이라 두 가지가 문제였다.

1. **규칙이 서버 소유인데 클라이언트가 복제했다.** 서버가 묶음을 바꾸면 조용히
   어긋난다
2. **다른 출처를 쓰다 코드 체계가 어긋났다.** KOSTAT 2013 기준이라 종로구가
   `11010`인데 서버는 현행 `11110`이었고, 252개 중 243개가 불일치했다. 게다가
   우연히 숫자가 겹치는 코드가 9개 있어(`31110`이 한쪽은 경기, 다른 쪽은 울산
   중구) 조용히 틀릴 수 있었다

지금은 출처가 하나이고 묶음은 서버가 정하므로 두 문제가 함께 사라졌다.

### 조립 비용

측정값(테스트 환경, 실기기 아님):

```
자산 읽기 + JSON 디코드    ~37ms
161칸 조립(dissolve+단순화) ~73ms
결과                       12,977점
```

앱 세션당 한 번이라 문제가 되지 않는다. 파싱은 isolate에서 한다
(`districtBoundariesProvider`).

## 좌표계 주의

값은 WGS84 경위도 그대로다. 화면에 그릴 때 **경도를 `cos(위도)`로 보정하지 않으면
가로로 늘어진다** — 36°N에서 경도 1도는 위도 1도의 약 0.81배다. 보정은
`CellProjection`이 한다.
