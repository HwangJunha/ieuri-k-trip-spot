# SPEC-0030 전국 지도 — 화면 설계

레퍼런스는 사용자가 준 **스크래치 아트 맵 포스터**(TRAVEL KOREA Scratch Art Map)다.
161칸으로 나뉜 한국 지도를 여행하며 한 칸씩 긁어 채우는 종이 제품이고, 긁어낸 칸이
**저마다 다른 색에 그 지역 그림**이 드러나는 것이 핵심이다.

## 레퍼런스를 어떻게 옮겼는가

| 포스터 | 앱 | 이유 |
|---|---|---|
| 하늘색 바다 | **바다를 그리지 않는다** (`surface`) | 배경을 비우면 칸이 주인공이 된다 |
| 회색 미긁힘 칸 | `surfaceDim` | 같은 웜 계열로 가라앉힌다. 회색을 쓰면 이 화면만 차가워진다 |
| 긁으면 나오는 **알록달록한 색** | **시도별 색**(`ProvincePalette`) | 아래 참조 |
| 칸마다 지역 **일러스트** | **랜드마크 유형 도형**(`LandmarkIcons`) | 아래 참조 |
| 칸 경계선 | 선 대신 배경색으로 벌린다 | 종이를 오려 붙인 느낌이 난다 |

### 색: 브랜드색 하나가 아니라 시도별로

처음에는 방문 칸을 브랜드 코럴 하나로 칠했다. **틀린 선택이었다** — 20칸을 채우든
100칸을 채우든 빨간 얼룩으로 보여 "채우는 재미"가 사라진다. 레퍼런스가 알록달록한
이유가 바로 그것이다.

지금은 17개 시도마다 색이 다르다. **인접 그래프를 놓고 배정했다** — 눈대중으로
고르면 맞닿은 곳이 비슷해진다(실제로 경북·경남이 RGB 거리 9로 거의 같았고, 경기·충북이
23이었다). 지금은 맞닿은 어떤 쌍도 거리 58 이상이고, 그 사실을 테스트가 지킨다.

경기는 브랜드 주홍으로 고정했다 — 칸이 31개로 가장 많아 지도의 인상을 좌우한다.

### 랜드마크: 실사진이 아니라 유형 도형

**서버는 161칸 전부에 대표 이미지를 준다**(경복궁·광안대교·서문시장·강화 고인돌…).
그런데 지도의 칸에는 그 실사진을 넣지 않는다. 두 가지 이유다.

1. **칸이 화면에서 20~60px이다.** 300×200 실사진을 그 안에 넣으면 무엇인지 안 보이고
   색 얼룩만 남는다. 레퍼런스가 실사진이 아니라 라인 일러스트인 이유이기도 하다
2. **161칸 중 56칸이 공공누리 제3유형(변경금지)이다.** 칸 모양대로 오리는 것은 형태
   변경이라 저촉될 수 있다(POL-051·R23)

그래서 랜드마크 **이름**에서 유형을 뽑아(`landmarkKindOf`) 유형별 단순 도형을 그린다.
161개 실제 이름을 보고 11개 유형으로 나눴다 — 산·사찰·성곽·한옥·바다·물·숲·다리·
특산품·도심·탑. "속리산 법주사"가 산이 아니라 사찰로 가도록 **구체적인 규칙이
일반 규칙보다 앞선다**.

**실사진은 버려지지 않는다.** 칸을 누르면 올라오는 시트와 지역 상세에서 크게 보여주고,
출처 표기(`attributionText`)도 거기서 함께 노출한다(R24). 작게 뭉개서 161장을 흩뿌리는
것보다 사진이 살고 저작권도 안전하다.

아이콘은 이미지 자산이 아니라 `Canvas` 도형이라 어느 배율에서도 또렷하고, 칸의 화면상
크기에 비례해 커진다. **22px보다 작은 칸에는 그리지 않는다** — 뭉개진 그림은 없느니만
못하다(161칸 중 14칸이 여기 걸린다).

> 한때 아이콘이 하나도 안 보였다. `mapCells` 조회가 `representativeImage`를 고르지
> 않아 유형을 뽑을 이름이 없었기 때문이다. 지도용 조각은 **`caption`만** 고른다 —
> 실사진 URL은 칸 상세에서 받는다.

## 화면 구성 — 지도가 주인공이다

처음에는 진척 바·지도·선택 바·탭을 세로로 쌓았다. **화면이 자잘해 보였다** — 지도가
작아지고 정보 줄만 늘어난다. 지금은 지도가 화면 전체를 쓰고 나머지는 비켜선다.

```
┌─────────────────────────────┐
│ ▓▓▓▓░░░░░░░░   ↗  🖼  📍   │  떠 있는 얇은 바(AppBar 없음)
├─────────────────────────────┤
│                             │
│      [161칸 지도 · 전면]      │  cover 모드로 세로를 채운다
│   시도별 색 + 랜드마크 도형    │  확대·이동 가능
│                             │
│         (제주까지 보인다)      │
└─────────────────────────────┘
```

**숫자를 적지 않는다.** "161칸 중 7칸"은 막대가 이미 보여주는 것을 글자로 반복할
뿐이고 지도를 가리는 값을 한다. 정확한 수치는 지역 상세에 있다.

**오른쪽 맨 끝이 현재 위치 등록(📍)이고 브랜드 코럴이다.** 지도를 채우는 주
동작이라 엄지가 가장 먼저 닿는 자리에 두고 색으로 구분한다.

**공유도 상단이다.** iOS는 내비게이션 바 오른쪽(Safari·사진·지도), Android는
앱바 액션이 표준이다. 하단 FAB에 두면 "이 화면의 주 동작"으로 읽혀 과하고,
지도 위에 떠서 어색하다.

**하단 여백은 `barExtent` + 12.** 바가 `SafeArea` 안에 있어 인셋까지 더하면
지도가 위로 떠 버린다(실제로 그렇게 했다가 크게 비었다). 12는 제주가 바에 닿아
보이는 것을 띄우는 값이다.

**내비 바 높이를 80 → 64로 낮췄다.** Material 기본값이 두껍게 느껴졌고, 라벨을
선택된 탭에만 보이므로(`onlyShowSelected`) 64면 아이콘+라벨이 넉넉히 들어간다
(렌더로 오버플로 없음을 확인). `barExtent`가 이 상수를 참조하므로 지도 여백도
자동으로 따라간다.

**칸을 누르면 아래에서 시트가 올라온다** — 이름·랜드마크 실사진·장소 몇 개·상세 버튼.
화면에 상시로 붙여 두지 않으니 지도가 넓어진다.

**`cover` 모드**: 지도의 실제 비율은 약 **1.06:1로 거의 정사각형**인데 폰 화면은 2:1
안팎이다. `fit`으로 맞추면 폭 기준이 되어 세로가 절반 가까이 빈다(실측: 화면 높이
760px 중 417px만 씀). 세로를 채우면 좌우로 넘치지만 그건 서해·동해의 빈 바다라
잘려도 무방하다.

### 확대·이동

**핀치와 더블탭 둘 다 된다.** 핀치만으로는 확대할 수 있다는 것을 알기 어렵다 —
지도가 처음부터 꽉 차 있어 더 커질 수 있다는 신호가 없다.

`GestureDetector`를 **쓰지 않는다.** 측정으로 확인한 것:

| 구조 | 단일 탭 | 더블탭 | 팬 |
|---|---|---|---|
| 안쪽 `GestureDetector(opaque)` | O | — | **X** |
| 바깥 `GestureDetector` | **X** | O | **X** |
| 안쪽에 `onDoubleTap` 추가 | **X** | O | **X** |

어느 조합도 셋을 다 살리지 못한다. `InteractiveViewer`가 자기 팬 인식기로 탭을
소비하고, `onDoubleTap`이 있으면 그것마저 경합에서 이겨 팬을 막는다.

그래서 `onInteractionStart/Update/End` 콜백에서 **탭·더블탭을 직접 판별한다** —
움직인 거리가 임계 이하면 탭이고, 300ms 안에 두 번이면 더블탭이다. 셋 다
동작하는 것을 `national_map_canvas_test`가 지킨다.

`boundaryMargin`을 무한으로 열어 확대했을 때 가장자리 칸까지 닿게 했다 —
기본값은 경계에서 막혀 서해 섬이나 울릉도에 닿지 못한다.

### 바텀 시트는 하단 탭을 피해야 한다

셸이 `extendBody: true`라 시트 아래쪽이 떠 있는 내비 바에 **그대로 가린다** — 실제로
"사진으로 채우기" 시트의 버튼이 탭 바 뒤로 들어가 눌리지 않았다. 시트마다 여백을 적지
않고 `showMapSheet` 한 곳에서 `barExtent`만큼 띄운다.

### 상태

| 상태 | 표시 |
|---|---|
| 로딩 | `CircularProgressIndicator` |
| 자산·조회 실패 | `nationalMapUnavailable` |
| 한 칸도 없음 | 빈 지도 + "사진으로 채우거나 지금 있는 곳을 등록해 보세요" (오류가 아니다, R32) |
| 칸 선택 | 아래에서 시트가 올라온다 — 이름·실사진·장소·상세 버튼 |

## 컴포넌트

`component/` 아래 이름이 그대로 파일명이다.

- **`CellPainter`** — 161칸을 그린다. 팔레트는 `CellPalette.of(scheme)` 한 곳에서
  나온다. 선택한 칸은 맨 위에 다시 그려 이웃 테두리에 가리지 않게 한다
- **`NationalMapCanvas`** — `InteractiveViewer` + 탭 히트 테스트. **화면과 같은
  투영을 써야** 누른 곳과 잡히는 칸이 어긋나지 않는다
- **`LandmarkIcons`** — 랜드마크 유형별 도형. 24×24 좌표계에 그리고 칸 크기에
  맞춰 배율을 준다
- **`CellSheet`** — 칸을 눌렀을 때 올라오는 시트. **랜드마크 실사진이 여기서 보인다**
- **`showMapSheet`** — 하단 탭을 피해 시트를 띄우는 공통 헬퍼
- **`ProvinceProgressBar`** — 시도 1곳의 진척 막대. **지금은 화면에 쓰지 않는다** —
  지역 상세에 "충청북도 11칸 중 3칸"을 띄웠으나, 가 본 적 없는 지역의 분모는
  사용자에게 뜻이 없어 걷었다. R21의 계산(`provinceProgressOf`)은 그대로 있다

## 보관함 (R18)

좋아요와 커뮤니티를 합치되 **두 화면의 내부는 건드리지 않는다.**

상단바를 보관함이 갖고 자식은 `showAppBar: false`로 본문만 그린다 — 그대로
액자에 넣으면 상단바가 두 줄이 된다. 토글은 `AppBar.bottom`에 두어 제목 아래
전체 폭을 쓴다.

```
┌─────────────────────────────┐
│ Spot Talk                    │  ← 활성 쪽의 이름
│ [ ♡ 좋아요 │ 💬 커뮤니티 ]    │  ← SegmentedButton
├─────────────────────────────┤
│  (자식 화면 본문 그대로)       │  IndexedStack
```

**제목이 토글 라벨과 다른 이유:** 커뮤니티 화면은 "Spot Talk"라는 고유 이름을
갖고 있어 토글 라벨("커뮤니티")로 대체하면 그 이름이 화면에서 사라진다.

자식은 `IndexedStack`에 둔다 — 토글할 때마다 목록을 다시 읽고 스크롤 위치를
잃으면 "보관함"이라는 이름값을 못 한다. 토글 선택 자체는 provider가 `keepAlive`로
들고 있어 탭을 떠나도 유지된다.

숨긴 글 진입점은 `CommunityScreen.hiddenPostsAction`으로 꺼내 보관함 상단바가
그대로 쓴다 — 커뮤니티를 보고 있을 때만 나온다.

## 하단 탭 (R17)

탭 수 5개와 둘러보기 가운데 강조는 유지한다.

| # | 탭 | 아이콘 |
|---|---|---|
| 0 | 홈 | `home` |
| 1 | **전국 지도** | `KoreaIcon`(한반도 실루엣) |
| 2 | 둘러보기 | 강조 퍽(그대로) |
| 3 | **보관함** | `bookmark` |
| 4 | 지도 | `map` |

전국 지도는 **한반도 실루엣을 직접 그린다**(`common/widget/korea_icon.dart`).
`Icons.public`(지구본)을 쓰던 것을 바꿨다 — 지구본은 "전국"이라는 뜻이 드러나지
않는다.

**남한만이 아니라 한반도 전체다.** "한반도"라고 하면 북한까지 포함한 모양을
뜻하고, 그 모양에서 제주는 보통 뺀다. 도형은 **Natural Earth**(퍼블릭 도메인)
1:110m 국가 경계에서 가져왔다 — 그 축척의 원본이 이미 남 19점·북 44점이라
아이콘에 그대로 쓸 만큼 단순하다.

**두 나라를 `Path.combine`의 union으로 합쳐 그린다.** 따로 그리면 미선택
(외곽선) 상태에서 국경선이 그어져 남북이 갈라져 보인다 — 한반도는 이어진
하나여야 한다. union은 싸지 않으므로 `static final`로 한 번만 만든다.

spot 지도는 `map`이다 — 둘 다 지도지만 하나는 "내가 채운 기록"이고 하나는
"지금 주변"이라 아이콘이 같으면 안 된다.

## 남은 것

디자인상 미구현은 없다. 실기기에서만 확인 가능한 것은
`problem/SPEC-0030-client.md`에 적었다 — 사진 스캔의 실제 EXIF 동작이 대표적이다.

아이콘은 코드로 그린 도형이라 손그림만큼 아기자기하지는 않다. 디자이너 에셋으로
교체하려면 `LandmarkIcons.paint`의 분기만 갈아 끼우면 되고, 분류(`LandmarkKind`)와
칸 크기 대응은 그대로 쓴다.
