# SPEC-0030 전국 지도 — 화면 설계

레퍼런스는 사용자가 준 **스크래치 아트 맵 포스터**(TRAVEL KOREA Scratch Art Map)다.
161칸으로 나뉜 한국 지도를 여행하며 한 칸씩 긁어 채우는 종이 제품이다.

## 레퍼런스를 어떻게 옮겼는가

**개념은 가져오고 색은 가져오지 않는다.**

포스터는 하늘색 바다, 회색 미긁힘 칸, 칸마다 그려진 지역 일러스트로 되어 있다.
그대로 옮기면 이 화면만 앱에서 떠 보인다 — 우리 앱은 웜 코럴 팔레트이고
표면이 `#FFF8F7`인 따뜻한 오프화이트다.

| 포스터 | 앱 | 이유 |
|---|---|---|
| 하늘색 바다 | **바다를 그리지 않는다** (`surface`) | 배경을 비우면 칸이 주인공이 된다. 파란 면을 넣으면 그 자체가 큰 색 덩어리가 되어 코럴과 부딪힌다 |
| 회색 미긁힘 칸 | `surfaceDim` (`#EFD4D0`) | 같은 웜 계열로 가라앉힌다. 회색을 쓰면 앱에서 이 화면만 차가워진다 |
| 은박을 긁어낸 컬러 | `primary` (`#B2211D`) | 브랜드색으로 채운다. "채웠다"가 곧 브랜드 경험이 된다 |
| 칸 경계선 | 선 대신 **배경색으로 벌린다** | 종이를 오려 붙인 느낌이 난다. 161칸에 선을 그으면 저줌에서 지저분하다 |
| 칸마다 지역 일러스트 | 넣지 않는다 | 161개 일러스트는 확보 불가능하다. 대신 칸을 누르면 서버가 주는 대표 이미지를 상세에서 본다(R9) |

미방문 색은 처음 `surfaceContainerHighest`(`#F8DCD9`)로 잡았다가 **실제로 그려
보고** 배경과 구분되지 않아 `surfaceDim`으로 한 단 내렸다. 미방문은 "빈 칸"이지
"비활성"이 아니다 — 채워야 할 칸이 몇인지 보여야 채우고 싶어진다.

## 화면 구성

```
┌─────────────────────────────┐
│ 전국 지도                    │  AppBar (앱 표준)
├─────────────────────────────┤
│ 전국          161칸 중 34칸  │  진척 요약
│ ▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░  │  LinearProgressIndicator, primary
├─────────────────────────────┤
│                             │
│         [161칸 지도]         │  CustomPaint + InteractiveViewer
│      방문=코럴 미방문=딤      │  (확대·이동, 새 질의 없음)
│                             │
├─────────────────────────────┤
│ 서울특별시                   │  선택한 칸
│ 서울특별시        [다녀왔어요] │  surfaceContainerLow 바닥
└─────────────────────────────┘
```

바닥 바는 하단 내비가 `extendBody: true`라 `FloatingBottomNavScaffold.barExtent`
만큼 띄운다.

### 상태

| 상태 | 표시 |
|---|---|
| 로딩 | `CircularProgressIndicator` |
| 자산·조회 실패 | `nationalMapUnavailable` |
| 한 칸도 없음 | 빈 지도 + "사진으로 채우거나 지금 있는 곳을 등록해 보세요" (오류가 아니다, R32) |
| 칸 미선택 | 바닥 바에 "지도에서 지역을 눌러 보세요" |

## 컴포넌트

`component/` 아래 이름이 그대로 파일명이다.

- **`CellPainter`** — 161칸을 그린다. 팔레트는 `CellPalette.of(scheme)` 한 곳에서
  나온다. 선택한 칸은 맨 위에 다시 그려 이웃 테두리에 가리지 않게 한다
- **`NationalMapCanvas`** — `InteractiveViewer` + 탭 히트 테스트. **화면과 같은
  투영을 써야** 누른 곳과 잡히는 칸이 어긋나지 않는다
- **`ProvinceProgressBar`** — 시도 1곳의 진척 막대. 완료면 체크 아이콘

## 보관함 (R18)

좋아요와 커뮤니티를 합치되 **두 화면의 내부는 건드리지 않는다.**

상단바를 보관함이 갖고 자식은 `showAppBar: false`로 본문만 그린다 — 그대로
액자에 넣으면 상단바가 두 줄이 된다. 토글은 `AppBar.bottom`에 두어 제목 아래
전체 폭을 쓴다.

```
┌─────────────────────────────┐
│ Spot Talk                    │  ← 활성 쪽의 이름
│ [ ♡ 좋아요 │ 💬 커뮤니티 ]    │  ← SegmentedButton
├─────────────────────────────┤
│  (자식 화면 본문 그대로)       │  IndexedStack
```

**제목이 토글 라벨과 다른 이유:** 커뮤니티 화면은 "Spot Talk"라는 고유 이름을
갖고 있어 토글 라벨("커뮤니티")로 대체하면 그 이름이 화면에서 사라진다.

자식은 `IndexedStack`에 둔다 — 토글할 때마다 목록을 다시 읽고 스크롤 위치를
잃으면 "보관함"이라는 이름값을 못 한다. 토글 선택 자체는 provider가 `keepAlive`로
들고 있어 탭을 떠나도 유지된다.

숨긴 글 진입점은 `CommunityScreen.hiddenPostsAction`으로 꺼내 보관함 상단바가
그대로 쓴다 — 커뮤니티를 보고 있을 때만 나온다.

## 하단 탭 (R17)

탭 수 5개와 둘러보기 가운데 강조는 유지한다.

| # | 탭 | 아이콘 |
|---|---|---|
| 0 | 홈 | `home` |
| 1 | **전국 지도** | `public` |
| 2 | 둘러보기 | 강조 퍽(그대로) |
| 3 | **보관함** | `bookmark` |
| 4 | 지도 | `map` |

전국 지도에 `public`, spot 지도에 `map`을 준다 — 둘 다 지도지만 하나는 "내가 채운
기록"이고 하나는 "지금 주변"이라 아이콘이 같으면 안 된다.

## 미구현

칸 상세(대표 이미지·출처 표기·spot 목록), 사진 스캔 확인 화면, 공유 화면은
서버 계약이 나온 뒤다. 현황은 `problem/SPEC-0030-client.md`에 있다.
