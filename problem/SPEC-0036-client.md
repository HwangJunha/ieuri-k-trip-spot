# SPEC-0036 — Client design

지도 탭이 그릴 장소를 고르는 기준을 무작위 셔플에서 추천 순서로 바꾸고, 「이 지역 재검색」의
의미를 **새로고침에서 다음 장소 더하기**로 바꾼다.

## Requirements this design answers

FR-001 · FR-002 · FR-003 · FR-004 · FR-005 · FR-006 · FR-007 · FR-008 · FR-009 · FR-010 ·
FR-011 · FR-012 · QR-001 · BR-001

`spec.md`(`Specs/SPEC-0036/spec.md`)가 원문이다. 여기에 문장을 옮겨 적지 않는다.

## Entry points

**새 화면도 새 진입점도 없다.** 이 스펙은 기존 지도 탭의 장소 선택 규칙만 바꾼다.
FR-003의 「더 보기를 요청할 수 있다」는 이미 존재하는 「이 지역 재검색」 버튼이 맡으며, 스펙이
「문구와 배치는 요구사항이 아니다」라고 명시했으므로 버튼을 새로 만들지 않는다.

| Requirement | Which screen | Which widget | What is added |
|---|---|---|---|
| FR-003 | `lib/domain/map/view/map_screen.dart` | `SearchThisAreaButton` (기존, `:987`) | 없음 — 의미만 「교체」에서 「누적」으로 바뀐다 |
| FR-008 | `lib/domain/map/view/map_screen.dart` | 같은 버튼의 표시 조건 `_canSearchHere` | 후보 소진 시 버튼이 다시 뜨지 않는 조건 |

FR-008은 「더 보기를 요청할 수단이 사라진다」이므로 **위젯을 더하는 것이 아니라 빼는**
요구사항이다. 안내 문구를 띄우지 않는다(T1 해소, 사용자 결정 2026-09-18).

## Decisions

| # | Decision | Rationale | Alternative rejected, and why |
|---|---|---|---|
| D-01 | 「이미 표시한 장소」는 `MapMarkerController`가 **세션 단위 집합**으로 들고 있다. 표시 판정용 키(`_servedKeys`)와 서버로 보낼 id(`_servedSpotIds`)를 각각 든다 — 키에서 id를 잘라내면 id에 콜론이 들어가는 순간 조용히 틀린 값을 보낸다 | 컨트롤러가 이미 `keepAlive`이고 마커 누적을 소유한다. 세션 경계 = provider 수명 = 앱 프로세스 수명이라 FR-005가 저절로 성립한다 | **`state`에서 역산**: 누적된 마커 목록이 곧 제외 목록이라 따로 안 들어도 된다고 볼 수 있으나, `_trim`이 화면 밖 오래된 마커를 버리므로 버려진 장소가 다시 후보가 된다 — FR-004 위반. 기록과 표시는 수명이 다르다. **디스크 저장**: FR-005가 세션 종료 시 소멸을 요구하므로 금지 |
| D-02 | `absorb`의 `if (replaceShown) unseen.shuffle();`(`:106`)를 **삭제**한다. 서버가 준 추천 순서를 그대로 쓴다 | BR-001(점수 외 기준 개입 금지) · QR-001(결정성). `thinMarkers`가 칸마다 「먼저 온 것」을 고르므로 순서를 유지하면 칸별 추천 상위가 뽑힌다 | **시드 고정 셔플**: 결정적이지만 여전히 점수가 아닌 기준이라 BR-001 위반 |
| D-03 | `replaceShown` 플래그를 **제거**하고 `absorb`를 항상 누적으로 만든다. 재검색은 「화면 안 마커를 갈아 끼우는 것」이 아니라 「제외 목록 밖의 장소를 더하는 것」이 된다 | FR-003 정정(2026-09-18): 더 보기는 교체하지 않고 10→20→30으로 누적한다. 교체 경로가 남아 있으면 그 자체가 스펙 위반 경로다 | **플래그 유지**: 자동 조회와 버튼 조회의 동작이 갈리면 FR-010(같은 조건)을 지키기 어렵고, 교체 분기(`kept`, `known`의 화면 안 되돌리기)가 D-01의 제외 목록과 정면으로 모순된다 |
| D-04 | `MapTuning.maxDrawnMarkers`(10)의 의미를 **화면 동시 표시 상한 → 한 번에 더해지는 수**로 바꾸고 이름을 `markersPerBatch`로 고친다. 누적 상한은 두지 않는다 | 스펙 §규모 가정이 「화면에 동시에 보이는 장소: 상한 없음」으로 확정. 이름을 그대로 두면 다음 사람이 화면 상한으로 오해한다 | **상한 유지**: FR-003이 요구하는 누적 자체가 불가능해진다 |
| D-05 | `MapTuning.maxRetainedMarkers`(60) 보관 상한은 **유지**하되 값을 재검토 대상으로 남긴다(T4) | 누적 상한이 없다는 것은 「스펙이 상한을 요구하지 않는다」이지 「메모리를 무한히 쓴다」가 아니다. `_trim`은 표시 정책이 아니라 메모리 방어선이다. 제외 목록(D-01)이 `_trim`과 무관하게 남으므로 버려진 마커가 되살아나지 않는다 | **상한 제거**: 한 세션이 길면 마커가 수백 개가 되고 사진 썸네일이라 렌더링이 무너진다. T4가 묻는 것이 정확히 이 값이다 |
| D-06 | 영역이 「바뀌었다」의 판정은 **기존 규칙을 그대로 쓴다** — `_lastMarkerArea!.contains(visible)` 실패 또는 줌 변경(`map_screen.dart:530-533`) | T2. 이미 실기기에서 다듬어진 규칙이고(epsilon 1e-5로 SDK 떨림 흡수), 스펙은 「현재도 규칙이 있다」며 이를 인정한다. 새 기준을 발명하면 검증되지 않은 값이 하나 더 는다 | **거리·시간 임계값 신설**: 근거 없는 상수가 늘 뿐이고 실기기 재튜닝이 필요하다 |
| D-07 | FR-010(같은 영역이면 같은 조건)은 **`_lastMarkerArea`에 보관된 bbox를 재사용**해 지킨다. 영역이 바뀌지 않았다고 판정되면 그때 화면에서 새로 산출한 bbox가 아니라 첫 조회에 쓴 bbox로 조회한다 | 스펙이 경고한 함정 2번(보충 조회가 조건을 빠뜨림)의 정확한 재발 지점. 지도를 미세하게 움직이면 `_visibleBounds()`가 매번 다른 bbox를 주므로, 같은 영역인데 다른 조건으로 조회하게 된다 | **매번 새로 산출**: 현재 동작이며 FR-010 위반. 「영역은 바뀌었거나 아니거나 둘 중 하나」라는 스펙 문장이 이 중간 상태를 금지한다 |
| D-08 | 소진 판정(FR-009)은 **서버가 요청한 수보다 적게 줬을 때**만 내린다. 판정 근거를 `MapRecommendationResult.exhausted`가 들고 온다 | 서버 계약이 「`first`보다 적게 오면 영역 안 후보가 소진된 것」으로 확정(2026-09-18). 클라이언트가 격자로 솎아 낸 뒤의 수로 판정하면 가짜 소진이다 — 솎여 못 그린 장소는 제외 목록에 없어 다음 요청에 다시 온다 | **새 항목 0개 = 소진**: 스펙이 명시적으로 금지. **`truncated` 사용**(초안 D-08a): 「이번 응답이 잘렸는가」이지 「영역 안에 더 있는가」가 아니고, 도심에서 거의 항상 참이라 소진이 판정되지 않는다 |
| D-10 | 추천 spot과 문화행사를 **두 쿼리로 나눠 병렬 조회**한다. 추천은 `mapRecommendedSpots`, 행사는 기존 `mapViewport.events` | 계약이 그렇게 나뉘었다 — 추천은 인증 필수, `mapViewport`는 인증 없이 도는 계약이라 합칠 수 없다. 순차로 부르면 왕복이 두 번이라 `.wait`로 병렬로 둔다 | **`mapViewport` 하나로 통합**: 서버가 거부했고 근거도 타당하다(행사와 `truncated`가 로그인에 묶인다) |
| D-12 | 세션 경계는 `ref.listenSignedOut(clear)`로 잡는다. **`watchSignedIn`을 쓰지 않는다** | watch면 인증 판정이 `loading`에서 `data`로 자리잡는 것만으로 `build()`가 다시 돌아 쌓아 둔 기록이 지워진다 — 실제로 첫 조회 직후 제외 목록이 통째로 날아가 「다음 장소」가 매번 같은 장소를 줬다(FR-004·FR-005 위반). 이 저장소의 `session_scope.dart`가 정확히 이 경우를 위해 `listenSignedOut`을 두고 있다 | **`watchSignedIn`**: 초안이 이랬고, provider 테스트가 잡았다. 관측해서 쌓아 두는 provider는 watch를 쓸 수 없다 |
| D-11 | 조회는 **`MapMarkerController.loadNextBatch`가 소유**한다. 화면은 repository를 모른다 | 제외 목록을 컨트롤러가 들고 있으므로 조회 인자를 만들 수 있는 곳도 거기다. view가 repository를 임포트하면 CLAUDE.md §3 위반이다 | **화면이 repository를 직접 호출**: 초안이 이랬고 analyzer가 아니라 레이어 규칙이 막았다. **family provider**: 제외 목록이 키에 들어가면 세션이 길수록 키가 커지고 매번 캐시 미스라, 캐시가 이득 없이 메모리만 쓴다 |
| D-09 | 문화행사 마커는 **세션 제외 목록에 넣지 않되, 지금 표시 중인 것과는 중복을 피한다**. 기록(`_servedKeys`)이 아니라 `state`와 견준다 | FR-012(범위 밖, 기존대로). 양쪽 다 틀릴 수 있다 — 제외 목록에 넣으면 재검색 한 번에 행사가 영구히 사라지고, 아무것도 안 견주면 같은 행사가 쌓여 같은 자리에 SDK 핀이 겹쳐 박힌다(`MapOverlayPainter`가 목록을 인덱스로 순회한다) | **spot과 동일 취급**: 행사가 지도에서 사라진다. **아무 판정도 안 함**: 핀이 중복된다 — 초안이 이랬고 리뷰가 잡았다 |

## Missing information

**없다.** 서버가 미결 T3·T5를 해소하고 계약을 확정했다(`ieuri-server#136`, 2026-09-18).

| 미결 | 결정 |
|---|---|
| T3 (영역 ↔ 추천 입력) | **사각형으로 후보를 조달하고 거리 요인만 bbox 중심점 기준.** 원으로 근사하지 않는다 — 내접원은 네 모서리가 빠져 화면에 보이는 장소가 추천 대상에서 빠지고(FR-002 위반), 외접원 + 사후 필터는 실효 후보 수가 뷰포트 종횡비에 따라 달라진다 |
| T5 (한 번에 점수를 계산하는 후보 수) | **2,000건.** dev 실측 기준(명동 20km 폭에서 4,054건) |
| 제외 목록의 소유자 | **클라이언트.** 「봤다」의 판정이 *마커로 실제 그려졌는가*라, 격자로 솎아 그리는 클라이언트만 안다 — 서버가 세션을 들면 그리지 않은 장소까지 「봤다」로 기록해 남은 후보를 잃는다(FR-009) |

계약은 **신규 루트 쿼리** `mapRecommendedSpots(bbox, excludedIds, categories, first)`이며
`[MapSpot!]!`을 준다. `mapViewport`는 인증 없이 도는 계약이라 그대로 두고, 추천만 별도
필드로 뺐다 — 거기에 넣으면 `events`·`truncated`까지 로그인에 묶여 계약이 깨진다.

**소진 판정이 `first`보다 적게 왔는가로 확정되었다** — D-08a가 요청한 「영역 안 총 후보
수」 대신 이 방식이 채택되었고, `truncated`에 기대던 잠정 판정(D-08)은 폐기했다. 도심에서
동작하지 않던 문제가 해소된다.

## Screens and states

지도 탭(`map_screen.dart`) 하나. 새 화면이 없으므로 **버튼 하나의 상태 전이**가 전부다.

| 상태 | 조건 | 버튼 |
|---|---|---|
| 조회 가능 | 영역이 바뀌었거나, 조회 뒤 `searchAgainDelay`(3초)가 지났고 후보가 남았다 | 보임 |
| 조회 중 | `_isSearchingArea` | 보임, 진행 표시로 바뀌고 입력 차단 |
| 소진 | 이 영역의 후보가 모두 표시되었다 (D-08 판정) | **사라진다. 안내 없음** (FR-008) |
| 영역 이동 | 새 영역으로 판정 | 다시 보임 — 소진은 영역 단위이지 세션 단위가 아니다 |

**빈 화면은 생기지 않는다.** 누적된 마커가 남아 있고, 소진되어도 표시된 것은 지우지 않는다.

오류는 기존 경로를 그대로 쓴다 — 조회 실패 시 `_lastMarkerArea`를 갱신하지 않아 버튼이 다시
뜨고 재시도할 수 있다(`map_screen.dart:399-402`).
